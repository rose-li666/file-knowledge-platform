## 已复现并修复

P2：`search.retry_text` 原先先提取正文，再使用对 pending/processing 幂等的 `queue_document`。索引已读取正文后正在推理，此时正文重试不会增加 generation，旧正文快照仍可能发布。若正文提取结果已变为失败，会出现正文失败而旧向量就绪的不一致。

使用隔离真实 HTTP 进程，在真实模型推理前暂停旧任务，发起正文重试；修复前观察 generation=1、state=processing，专项退出1。修复后在正文锁内先事务提交新 generation，再提取正文；旧任务在最终提交时被代次检查阻止。语义查询额外要求正文 ready。真实模型释放后验证只有 generation=2 的片段、attempts=2，下载 SHA 一致、来源代次一致。普通索引重试仍保留 pending/processing 幂等，三次重复请求没有多任务或额外尝试。失败与成功原始证据均保留在 evidence/m6。

文档修正：README 一次性验证原先 --rm 会丢失容器内完整 JSON，改为先 docker cp 再移除验证容器；崩溃规则中的历史“尚未实现”、意图字段和宽限期描述按实际代码修正。

## 范围内确认与限制

- 原文件存储键随机，文件名拒绝路径/控制字符，下载验证存储键、实际字节大小及 SHA；正文提取独立于原文件提交。
- 上传元数据和任务同事务；任务先持久化 processing，再生成向量，事务原子替换片段，代次隔离迟到结果；单目录所有权锁、Web worker=1、索引消费=1、模型推理锁串行。
- 关键词使用参数化 literal instr；语义查询 SQL 使用当前文件分类、归档和任务代次过滤，没有旁路重排或复用 M1 向量。
- SQLite 精确向量检索适合考核的小资料集；未压测大规模库。单文档最多2000片段，超出仍可保存下载。
- 同一文件再次上传会产生独立文件记录，不提供上传内容去重/版本功能；索引重试片段唯一与此不同。
- PDF 仅文件头校验、名称搜索和原文件下载，正文提取仍未实现；新增预览接口复用原文件校验，显示依赖浏览器。文本编码失败会报告并允许重试，但原始编码未变时不应声称重试能修复。
- 本地演示版未实现登录/权限；配置无密钥，.env 排除提交。本次部署没有引入外部存储/队列或云 API。
- M6阶段普通Chrome人工核对当时待回复；最新已确认范围见user-validation.md。内置浏览器、截图或代码审查不替代人工证据。
